# Axum API Template

A complete template for REST APIs using Axum, built on modular architecture best practices.

## 🎯 How to Use This Template

### Option 1: Use the GitHub Template
1. Click **"Use this template"** at the top of the page
2. Create your new repository
3. Clone the repository you created
4. Follow the setup steps below

### Option 2: Manual Clone
```bash
git clone https://github.com/jospnunes/axum-api-template.git my-project
cd my-project
rm -rf .git
git init
git add .
git commit -m "Initial commit from template"
```

## 🚀 Features

- **Axum** - Modern, high-performance web framework
- **JWT Authentication** - Complete system with access/refresh tokens
- **PostgreSQL + Diesel** - Type-safe ORM for Rust
- **Middleware** - Rate limiting, CORS, error handling
- **Validation** - Robust input validation
- **Tests** - Integration test structure
- **Modular Architecture** - Handler → Service → Repository pattern

## 📋 Prerequisites

- **Rust** (1.70+)
- **PostgreSQL** (12+)
- **Diesel CLI**

## ⚙️ Setup

### 1. Install Diesel CLI
```bash
cargo install diesel_cli --no-default-features --features postgres
```

### 2. Set Up the Database
```bash
# Create the databases

# Set up environment variables
cp .env.example .env
```

### 3. Edit the .env file
```env
# Database
DATABASE_URL=postgresql://username:password@localhost/api_template_dev
TEST_DATABASE_URL=postgresql://username:password@localhost/api_template_test

# JWT Secrets
JWT_ACCESS_SECRET=your-super-secret-access-key-here
JWT_REFRESH_SECRET=your-super-secret-refresh-key-here

# Server
SERVER_HOST=127.0.0.1
SERVER_PORT=3000

# CORS
CORS_ORIGIN=http://localhost:3000

# Rate Limiting
RATE_LIMIT_REQUESTS_PER_MINUTE=60
RATE_LIMIT_BURST=10
```

### 4. Run Migrations
```bash
diesel migration run
```

### 5. Run the Application
```bash
cargo run
```

The API will be available at `http://localhost:3000`

## 🔧 Development

### Adding New Modules

1. **Create the structure:**
   ```bash
   mkdir src/my_module
   touch src/my_module/{mod.rs,my_handler.rs,my_service.rs,my_repository.rs,my_dto.rs}
   ```

2. **Follow the architectural pattern:**
   - **Handler**: Receives HTTP requests, validates input, calls the service
   - **Service**: Business logic, orchestrates repository calls
   - **Repository**: Data access, Diesel queries
   - **DTO**: API input and output structures

3. **Register routes** in `routes/mod.rs`

### Migrations

```bash
# Create a new migration
diesel migration generate create_my_table

# Run migrations
diesel migration run

# Revert the last migration
diesel migration revert

# Redo the last migration
diesel migration redo
```

### Tests

```bash
# Run all tests
cargo test

# Run specific tests
cargo test auth_test

# Run with logs
cargo test -- --nocapture
```

## 🌐 API Endpoints

### Health Check (Public)
- `GET /health` - Basic application status
- `GET /ready` - Readiness check (includes database connection)

### Authentication (Public)
- `POST /auth/register` - Register a new user
- `POST /auth/login` - Log in with email/password
- `POST /auth/refresh` - Refresh the access token
- `POST /auth/forgot-password` - Request a password reset
- `POST /auth/reset-password` - Reset the password with a token

### User (Protected)
- `GET /api/user/profile` - Get the user profile
- `PUT /api/user/profile` - Update the user profile
- `POST /api/logout` - Log out (revokes tokens)

### Request Examples

```bash
# Basic health check
curl -X GET http://localhost:3000/health

# Readiness check
curl -X GET http://localhost:3000/ready

# Register a user
curl -X POST http://localhost:3000/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Jane",
    "last_name": "Doe",
    "email": "jane@example.com",
    "password": "password123"
  }'

# Login
curl -X POST http://localhost:3000/auth/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane@example.com",
    "password": "password123"
  }'
```
